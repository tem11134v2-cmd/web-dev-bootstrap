Ты — оркестратор (полные правила: `docs/orchestration.md`). Цель волны: $ARGUMENTS

> Эта команда — **явный** вход в режим. При крупной задаче (целая спека 02–12, rollout, recreate/redesign, 3+ однотипных страниц) Claude обязан входить в оркестраторный режим **сам**, без команды — маршрутизация описана в `CLAUDE.md` § Multi-Claude protocol.

Сделай следующее:

1. Прочитай ТОЛЬКО: `docs/orchestration.md` (правила режима — единственный docs-файл, который оркестратор читает, один раз при входе), `CLAUDE.md`, `specs/INDEX.md`, `.claude/memory/INDEX.md`, `.claude/memory/project_state.md` (включая `## Task ledger`), целевую спеку (или спеки) из аргумента. Остальной `docs/` НЕ читай — их читают субагенты по спискам «KB files to read first». Код не читай и не пиши, браузер не открывай.

2. Построй план волны:
   - какие спеки/страницы входят и в каком порядке;
   - какой агент на что — по строке `> Оркестрация:` в шапке каждой целевой спеки (правила режима ты уже прочитал в `docs/orchestration.md` — единственном docs-файле, который оркестратор читает, при входе; определения агентов — `.claude/agents/`);
   - что запускается параллельно, что строго последовательно (конфликтные файлы — только integrator; 08 и 09 — последовательно; 11 — соло);
   - где после волны нужен verifier (крупные пласты: 03, 04, 06, 08+09, 11);
   - все HITL-пункты волны: ключи, доступы, подтверждения заказчика, выбор вариантов.

3. Покажи план человеку + **ОДИН батч-вопрос**: все HITL-пункты списком сразу. Не задавай вопросы по одному по ходу волны. Жди явного «ОК».

4. После «ОК»:
   - составь самодостаточные брифы (формат — в `docs/orchestration.md`: задача + спека + KB files + выжимка памяти ≤5 строк + Boundaries + Done when);
   - запускай агентов; после каждого — принимай структурированный отчёт, разбирай отклонения и вопросы;
   - фиксируй каждую задачу в `## Task ledger` файла `project_state.md`: задача | агент/модель | статус | верификация | коммиты;
   - две неудачи одного агента → перезапуск с новым брифом; снова провал → эскалация человеку (НЕ дожимать, НЕ /clear).

5. По завершении волны:
   - запусти verifier на пласт (если положен по плану), приложи ему ТОЛЬКО «Done when» и артефакты;
   - обнови `project_state.md` (Active phase/spec, Next steps, ledger) и остальную память по триггерам из `CLAUDE.md` — память пишешь только ты;
   - дай человеку сводку: сделано / fail-пункты verifier / вопросы / план следующей волны.
