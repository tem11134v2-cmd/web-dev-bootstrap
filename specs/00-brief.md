# Spec 00: Приём брифа и материалов проекта

> Оркестрация: интерактив (оркестратор/человек), субагенту не отдаётся; параллель: нет; verifier: не нужен (гейт = подтверждение пользователя)

## KB files to read first

- `.claude/memory/INDEX.md`

## Goal

Принять от пользователя готовые материалы предпроектной работы (бриф, анализ конкурентов, структуру страниц, тексты, медиа), разложить их в `docs/` и `public/`. Обнулить шаблонную память под новый проект, завести `CLIENT-TODO.md`, выбрать источник дизайна. Зафиксировать в памяти ключевые решения и табу заказчика. Подготовить почву для всех последующих спек.

## Background

Предпроектная работа (бриф клиента, SEO-анализ, написание структуры и текстов) идёт ВНЕ Claude — пользователь делает её сам с MCP (Keyso, JustMagic, Wordstat и др.) или вручную. На входе в Claude он приносит готовые `.md` файлы или экспорт со старого сайта (например, Tilda).

Этот спек — **точка приёма**, а не точка генерации. Если каких-то материалов нет — спросить пользователя, а не выдумывать.

## Входные форматы (что приносит пользователь)

Один из вариантов или их комбинация:

### Вариант A: Готовые .md файлы

Пользователь даёт пути к файлам:
- `brief.md` — бизнес, ЦА, услуги, бренд (цвета, тон), контакты, домен
- `competitors.md` — анализ ТОПовых конкурентов (URLs, что у них есть, чему учиться)
- `structure.md` или `pages.md` — древовидный список страниц
- `content/*.md` — тексты по страницам (один файл = одна страница)
- `media/` — папка с лого, фото, шрифтами

### Вариант B: Действующий сайт (миграция)

- ZIP-выгрузка из Tilda / URL действующего сайта / CMS-доступ
- **Сохранить контент + SEO** (тексты, медиа, 301-редиректы) → `specs/optional/opt-migrate-from-existing.md` (параллельно/перед 00).
- **Сохранить дизайн 1:1** — см. маршрут D в развилке ниже.

## Развилка: источник дизайна

Выбрать вместе с пользователем ДО начала кода — от этого зависит маршрут после `02-project-init`:

| | Источник дизайна | Маршрут |
|---|---|---|
| A | Готовый макет (Claude Design / HTML / скрины) | `specs/optional/opt-design-to-site.md` — забор макета, извлечение токенов, компонентизация на стек, parity-check во встроенном браузере |
| B | Референсы конкурентов (URL) | `specs/optional/opt-design-from-references.md` — извлечь паттерны (не 1:1), собрать дизайн-бриф, согласовать → дальше классические 03/04 |
| C | С нуля по брифу | Классические `03-design-system` → `04-homepage-and-approval` |
| D | Перенос действующего сайта 1:1 | `specs/optional/opt-visual-recreate.md` — визуальная копия донора по computed-styles, заменяет 03–06 (обычно вместе с `opt-migrate-from-existing.md`) |

Граница между B и D: B — **синтез** паттернов из нескольких источников, D — **копия** одного донора. Выбор зафиксировать в `decisions.md` с **Why:**.

## Tasks

1. **Обнулить шаблонную память под новый проект:** `.claude/memory/project_state.md` → чистое состояние (реальное имя проекта, Active phase = `00-brief`, пустой Session log, пустой Task ledger). Проверить, что `pointers.md` пуст (в шаблоне он пустой; если там остались записи шаблона — удалить)
2. Спросить пользователя: какие материалы он передаёт, где они лежат; пройти развилку «Источник дизайна» (см. выше)
3. Прочитать все переданные файлы целиком
4. Создать `docs/spec.md` — выжимка из брифа: бизнес, ЦА, услуги, бренд (цвета HEX, шрифт, тон), контакты, домен, основные SEO-запросы
5. Создать `docs/content.md` — собранные тексты по страницам в едином формате (заголовок страницы → текст по секциям)
6. Создать `docs/pages.md` — структура страниц как Markdown-таблица:
   ```
   | URL | H1 | Title | Description | Приоритет | Статус | Родитель |
   ```
7. Создать `docs/integrations.md` — что планируется (CRM, аналитика, домен, внешние сервисы) — заполнено настолько, насколько известно сейчас, остальное по ходу
8. Скопировать медиа в `public/images/`, лого в `public/logo.svg` (если есть)
9. **Создать `CLIENT-TODO.md`** в корне проекта из `specs/templates/client-todo-template.md` и внести первые известные пункты (доступ к DNS/регистратору, недостающие тексты/фото, будущие подтверждения и верификации). Дальше файл пополняется по триггеру: понял, что нужно что-то от заказчика → сразу строка в `CLIENT-TODO.md`
10. Записать в память:
    - `decisions.md` — ключевые решения брифа (URL-структура, выбор CRM, отказ от/выбор технологий) + выбранный источник дизайна (A/B/C/D) с **Why:**
    - `feedback.md` — табу и правила заказчика с **Why:** (нет фото юристов, не использовать слово X, бренд-цвета, и т.д.)
    - `references.md` — домен, планируемая CRM, контакты заказчика
    - `project_state.md` — отметить `00-brief` как done, следующая спека `01a-local-setup`; зафиксировать маршрут после 02 (03 / opt-design-to-site / opt-design-from-references / opt-visual-recreate)
11. Показать пользователю summary: «Прочитал бриф. Понял: [3-5 ключевых пунктов]. Источник дизайна: [A/B/C/D]. Зафиксировал в памяти: [список]. Готов к 01a-local-setup. Что-то добавить/исправить?»

## Boundaries

- **Always:** читать переданные файлы целиком, задавать уточняющие вопросы при противоречиях
- **Ask first:** если в брифе нет цветов / контактов / домена — спросить, не выдумывать; выбор ветки дизайна — всегда за пользователем
- **Never:** создавать `docs/spec.md` из своей фантазии, генерировать тексты «вместо» пользователя, начинать кодить

## Done when

- Память обнулена: `project_state.md` в чистом состоянии под этот проект, `pointers.md` пуст
- `docs/spec.md`, `docs/content.md`, `docs/pages.md`, `docs/integrations.md` созданы и заполнены реальными данными
- Медиа разложено в `public/`
- `CLIENT-TODO.md` создан, первые известные пункты внесены
- Источник дизайна выбран и записан в `decisions.md`
- Память обновлена: `decisions.md`, `feedback.md`, `references.md`, `project_state.md`
- Пользователь подтвердил summary

## Memory updates

- `decisions.md` — все не-очевидные решения брифа + источник дизайна
- `feedback.md` — табу и правила (с **Why:**)
- `references.md` — домен, CRM, контакты, ID счётчиков (если уже известны)
- `project_state.md` — фаза «brief done, ready for infrastructure», маршрут после 02
