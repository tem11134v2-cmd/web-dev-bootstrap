# Spec [opt]: Дизайн с нуля на референсах

> Оркестрация: builder-opus СОЛО (владеет браузером); параллель: нет; verifier: не нужен (гейт = выбор направления человеком)

## Когда применять

Маршрут **B** развилки «Источник дизайна» (спека 00): готового макета нет, но есть 2–5 сайтов (конкуренты, просто нравящиеся), на которые хочется равняться. Встраивается **перед / вместо первой половины 03**: результат — согласованный дизайн-бриф, с которым `03-design-system` → `04` идут как обычно, только выбор направления уже сделан осознанно, а не «с нуля по брифу».

**Явная граница с `opt-visual-recreate`:** здесь — **СИНТЕЗ** (вдохновение несколькими источниками: паттерны, не пиксели), там — **КОПИЯ** одного донора 1:1. Нужен перенос конкретного сайта — это recreate.

## KB files to read first

- docs/design-motion.md (каталог паттернов — на него мапятся подсмотренные приёмы)
- docs/design-system.md (формат токенов — что в итоге пойдёт в 03)
- docs/spec.md (бренд, ЦА, тон)
- `.claude/memory/feedback.md` (табу заказчика)

## Goal

Из 2–5 референсов извлечь **паттерны, не пиксели**, собрать дизайн-бриф «решение | у кого подсмотрено | как адаптируем», предложить 2–3 варианта направления, дать человеку выбрать — дальше обычные 03/04 с этим брифом.

## Tasks

### 1. Вход от человека

1. Спросить: 2–5 URL референсов + **что нравится в каждом** (хотя бы одним словом: «палитра», «как поданы кейсы», «шрифт»). Без этой пометки извлечение расфокусировано — не начинать без неё.

### 2. Осмотр референсов (встроенный браузер)

2. Открыть каждый: `tabs_create` → `navigate`. Предупредить человека: первый заход на каждый внешний origin требует одноразового одобрения (per-origin approval) — их будет столько, сколько референсов. Каждый вызов — с явным `tabId`.
3. По каждому референсу извлечь **паттерны, не пиксели**:
   - палитра-настроение (тёмная/светлая, температура, где акценты) — НЕ точные HEX;
   - типографический масштаб (контраст заголовков/текста, акцидентный шрифт или нет);
   - приёмы секций и подачи — соотнести с каталогом `docs/design-motion.md` (bento, sticky, marquee, табы, степперы...);
   - интерактив (что движется, что раскрывается, что по hover);
   - **что берём / что НЕ берём** — и почему.
4. Инструменты: `computer screenshot` + `zoom` по регионам; `get_page_text` — структура и порядок секций; `resize_window {preset:"mobile"}` — как референс ведёт себя на мобильном.

### 3. Дизайн-бриф

5. Собрать таблицу: **решение | у кого подсмотрено | как адаптируем под наш бренд/контент**. Строки: палитра, типографика, hero-подача, 3–4 ключевых паттерна секций, интерактив.
6. Предложить **2–3 варианта направления** (как в токен-выборе спеки 03): например «строгий тёмный (реф 1) + bento (реф 3)» против «светлый воздушный (реф 2) + степперы». По каждому — 3–5 строк, чем отличается и кому подходит.
7. Человек выбирает → зафиксировать бриф в `docs/spec.md` (раздел «Дизайн-направление») и `decisions.md` с **Why:**.

### 4. Дальше

8. Обычные `03-design-system` → `04-homepage-and-approval` — токены и паттерны берутся из согласованного дизайн-брифа.

## Юр-примечание

Вдохновляться паттернами — нормально. **Переносить чужие тексты, фото, иллюстрации, логотипы — нельзя** (авторские права). Точное копирование раскладки + палитры + шрифтов одного чужого сайта — уже не синтез; легальный перенос 1:1 существует только для сайта самого заказчика (`opt-visual-recreate`).

## Boundaries

- **Always:** пометка «что нравится» по каждому референсу ДО осмотра; паттерны мапить на каталог design-motion; фиксировать и «что НЕ берём»; выбор направления — всегда за человеком.
- **Ask first:** добавить референс, которого человек не давал (нашёл «похожий хороший» сам); больше 5 референсов (расфокус).
- **Never:** снимать точные токены референса (HEX/шрифт в лоб) как «наши»; переносить чужие тексты/фото/лого; превращать синтез в копию одного сайта (это recreate).

## Done when

- Все референсы осмотрены (десктоп + мобайл), по каждому — паттерны и «берём / не берём»
- Дизайн-бриф-таблица собрана (решение | у кого | как адаптируем)
- 2–3 направления предложены, человек выбрал одно
- Выбор зафиксирован в `docs/spec.md` и `decisions.md`
- Готово к `03-design-system` с этим брифом

## Memory updates

- `decisions.md` — выбранное направление с **Why:**, отвергнутые варианты (чтобы не предлагать снова)
- `references.md` — URL референсов
- `project_state.md` — done, следующая `03-design-system`
