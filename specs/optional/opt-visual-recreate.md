# Spec [opt]: Перенос-реконструкция дизайна (визуальная миграция Tilda/WP/конструкторов)

## Когда применять

Заказчик приносит **действующий сайт** (Tilda, WordPress, Wix, любой конструктор), и нужно перенести его на наш Next-стек, **сохранив дизайн-идею один-в-один (90–95%)**, но без выгрузки кода и переделки чужой вёрстки.

- **Заменяет** основные `03-design-system` → `06-subpages-rollout` (по паттерну `opt-ecommerce`, который замещает 05–06).
- **Композируется с** `opt-migrate-from-existing.md`: тот тянет контент/медиа/URL и держит SEO-наследие (301), этот строит дизайн. Запускать opt-migrate **первым** (или параллельно §1–§4) — его артефакты (`docs/content.md`, `public/images/migrated/`, карта редиректов) являются входом для этой спеки.
- **Возврат в основной поток:** после реконструкции — `08-seo` → `09-forms` → `10-analytics` → `11-performance` → `12-handoff`. Отдельной «спеки дозакрытия» нет — это и есть дозакрытие.
- **Когда НЕ применять:** дизайн донора слабый/типовой → быстрее собрать с нуля по `00-brief`. Контентный монстр (блог/каталог 100+ страниц) → сначала тянуть контент через CMS API (WP — REST `/wp-json/wp/v2/`), реконструкцию применять только к шаблонам страниц.

## Goal

Воссоздать дизайн действующего сайта-донора на нашем Next-стеке с верностью **90–95%**, извлекая токены, контент и ассеты из **живой отрендеренной страницы** (computed styles + DOM + CDN), посекционно, с авто-проверкой каждой секции через visual-diff. Не выгрузка кода, не «на глаз».

## Background

Выгрузка кода из конструкторов (Tilda — абсолютное позиционирование на фикс-артборд + генерёные классы; WP — PHP/темы/вывод плагинов) даёт модели **шум**: приходится одновременно reverse-инжинирить намерение, переводить чужую парадигму вёрстки и достраивать невидимые ассеты → дрейф, «не тот сайт, половина дизайна другая, фоток нет». Вывод: выгрузка кода окупается только при reuse «как есть» на той же архитектуре.

Разворот: смотреть на **отрендеренный результат** и **извлекать данные** (точные значения через `getComputedStyle`, текст verbatim, реальные URL ассетов), а не угадывать. **Скриншот — для проверки, не для съёма значений.**

**Валидация (rus-campers.com, Tilda):** детект → токены (палитра `#f84545`/`#363636`/`#a1a1a1`, Druk Wide + TildaSans, контейнер 1200px, пилюли r30, 73 ассета) → чистый захват (cookie-баннер) → сборка hero из токенов + реальный шрифт/фото с CDN → visual-diff → **v1 86% → v2 94% → v3 97% за 2 итерации.** Метод подтверждён на живом сайте.

## Requirements

### R1. Инструментарий
- Chrome-плагин (`mcp__Claude_in_Chrome__*`): `navigate`, `javascript_tool` (computed styles — ядро), `get_page_text`, `read_network_requests`, `find`, `computer` (screenshot / scroll / hover / click).
- Превью копии: `navigate` отвергает `file://` (подставляет `https://`) → поднять локальный статик-сервер (`node`-сервер или `pnpm dev`) и `navigate` на `http://localhost:PORT`.
- Браузер — **один серийный ресурс**: extraction и съёмка сериализуются (важно для fan-out, R10).

### R2. Детект платформы (дёшево, информирует квирки)
Скачать HTML, искать сигнатуры: `tildacdn`/`t-rec` (Tilda), `wp-content`/`wp-json` (WP), `wixstatic` (Wix), `bitrix`. Платформенных веток в v1 нет, но детект задаёт ожидания (Tilda — абсолют → переинтерпретировать в поток/grid; WP — пагинация/REST).

### R3. ⭐ Система умного захвата — «ряд нужных скринов со смысловой обработкой»
Цель — не один кадр, а **план захвата на секцию**: набор скриншотов, каждый со своим смыслом. Перед сборкой секции пройди по матрице и собери нужные кадры:

| Случай | Что делает алгоритм | Кадр |
|---|---|---|
| **Базовый** | скрин секции в 3 вьюпортах (360 / 768 / 1440) | `base@{vw}` |
| **Попап/оверлей перекрывает** | детект перекрытия → закрыть (× или «Принять» — для cookie/баннеров ок; либо JS `display:none` по позиционированному контейнеру) → переснять. **Self-check: повторять до чистого кадра** | `clean@{vw}` |
| **Слайдер/карусель** | перечислить **ВСЕ** слайды из DOM (bg-image / `<img>` / data-атрибуты), пролистать и снять каждый | `slide@{n}` |
| **Ховер/дропдаун/тултип** | `computer hover` на триггере → снять открытое состояние | `hover@` |
| **Аккордеон/таб/попап по клику** | `find` → клик по ref → снять раскрытое состояние | `state@` |
| **Блок не влезает в экран** | `resize_window` в высоту **НЕ** растит скриншот (кап ~773px). → `scrollIntoView` по геометрии целевого блока, либо мелкий скролл-шаг + склейка тайлов | `stitched@` |

Правила захвата:
- **Координатные клики ненадёжны**, когда высота окна ≠ высоте скриншота → клик через `find`→ref или JS, не по сырым координатам.
- Попапы: для cookie/маркетинговых баннеров клик/JS-hide — **ок**. **Никогда** не подтверждать OAuth / аккаунтные / платёжные согласия.
- Динамику (меняется со временем — авто-слайдер, авто-попап) ловить **из DOM**, а не одним кадром.

### R4. Извлечение токенов (computed styles)
Через `javascript_tool` + `getComputedStyle` по видимым элементам: палитра (цвета текста/фона по частоте), шрифты (заголовки vs текст), type-scale (`font-size`/`line-height`/`font-weight`/`letter-spacing`), радиусы, тени, ширина контейнера, брейкпоинты, `:root` CSS-переменные. Кросс-доменные `<link>`-стили недоступны через `cssRules` (CORS) — для `@font-face`/woff2 `curl`-ить CSS/HTML напрямую.

### R5. Ассеты — скачать, не воссоздавать
Реальные URL картинок/лого/иконок(SVG)/шрифтов/видео из DOM и network. Скачать → прогнать через `sharp`/`next/image` + `cloudinary-publish-mcp` → `public/images/migrated/` (общая папка с opt-migrate). **Фото никогда не «рисуем».** Шрифты: определить семейство; **лицензионные (напр. Druk Wide) в прод только при лицензии клиента** — иначе близкий бесплатный аналог + пометка.

### R6. Секции — по геометрии/содержимому, не по индексу
Первый `.t-rec`/`<section>` бывает нулевой высоты/служебный (на rus-campers hero был секцией №4, а не №0). Находить секции по видимой высоте и содержимому; собрать **карту секций** (тип, высота, текст-семпл) — это и цели для посекционной сборки/fan-out.

### R7. Цикл сходимости (атом builder→verifier)
На каждую секцию:
1. собрать React+Tailwind из **токенов** (не из скрина на глаз);
2. отрендерить локально → снять копию в тех же вьюпортах;
3. **verifier (структурно, не holistic):** баллы по измерениям [layout / типографика / цвет / отступы / ассеты / контент] + overlay-diff (полупрозрачный оригинал поверх копии — объективная улика по сетке) + программные проверки (все ассеты на месте? текст совпадает со скрейпом?);
4. fail → фикс по списку → повтор, **максимум ~4 итерации**; не сошлось → флаг «needs review» и дальше (graceful, без вечного цикла).

### R8. Допуск 90–95% + лог отклонений
Не пиксель-перфект. Очевидные баги донора (асимметрия отступов, кривой кегль) чинить **эвристиками нормализации** (снап на шкалу отступов/типа, симметрия) и **записывать в лог отклонений** — чтобы verifier не считал намеренную правку ошибкой, а заказчик видел, что улучшено. «Свежее, но узнаётся как тот же сайт».

### R9. Полный автомат на самопроверках
Без человеческих гейтов: swatch-проверка токенов **до** сборки; посекционная сходимость с лимитом; финальный отчёт (баллы / флаги / лог). Опционально — разовая ручная калибровка шага токенов на первом доноре.

### R10. Мультиагент — фаза 2 (после калибровки одного потока)
Сначала наладить и откалибровать **ОДИН** поток builder→verifier. Затем: серийный фундамент (extract один раз → токены + layout + hero, заморозить как общие артефакты) → параллельный **fan-out по секциям** с **независимым verifier** (не самооценка builder'а). Атом сразу делать parallel-ready: читает замороженные артефакты (не ходит на live), чистый I/O-контракт, файлы без коллизий (один компонент на секцию). Оркестрация — инструмент Workflow.

## Tasks

1. **Детект** — скачать HTML донора, определить платформу (R2). Записать в `docs/spec.md`.
2. **Карта** — список URL (из opt-migrate / sitemap); для каждой страницы — карта секций по геометрии (R6).
3. **План захвата** — на каждую секцию составить набор скринов по матрице R3 (база / чисто / слайды / состояния / склейка).
4. **Извлечение** — токены (R4) + контент verbatim (`get_page_text`) + манифест ассетов (R5). Заморозить в артефакты (`docs/spec.md` — токены, `docs/content.md` — тексты).
5. **Swatch-гейт** — собрать токены в наглядную палитру/type-scale, сверить с монтажом оригинала (авто-проверка R9). Прокинуть токены в `globals.css` (стык с `03-design-system`).
6. **Ассеты** — скачать, оптимизировать, перевыложить (R5).
7. **Hero + одобрение** — собрать первую секцию, прогнать цикл R7 до 90–95% (паттерн `04-homepage-and-approval`).
8. **Rollout секций** — остальные секции главной через цикл R7 (последовательно; fan-out — фаза 2, R10).
9. **Страницы** — повторить §2–§8 для остальных страниц из `docs/pages.md`.
10. **Отчёт** — таблица секций (баллы по измерениям, флаги, лог отклонений).
11. **Возврат в поток** — передать в `08-seo` (берёт редиректы из opt-migrate) → `09` → `10` → `11` → `12`.

## Мультиагент и каденс (эмпирика 2026-06-03, проверено на rus-campers)

Для визуального переноса **мультиагент даёт малую выгоду** — узкое место это браузер (один, привязан к основной сессии, сериализуется в любом случае). Fan-out-агенты **НЕ могут надёжно сами ходить в браузер** (прогон: 2 агента, 42 tool-use, 0 файлов на диске, без StructuredOutput). Если всё же использовать — **только frozen-artifact**: главный цикл извлекает (скрин на диск + контент + ассеты), агенты пишут компоненты **без браузера**, читая артефакты.

**Проще и качественнее: строить батчами секций по сессиям** — ритм твоего же `INDEX.md` «одна спека = одна сессия = один коммит». Каденс **front-loaded, а не «одна сессия на страницу» жёстко:** первая страница тяжёлая (строит переиспользуемый набор компонентов — Header / Footer / feature-строка / карточка модели / CTA-блоки), следующие — быстрая сборка из готового. Между сессиями — файл прогресса (`project_state`-стиль: готово / осталось / замороженные токены / список компонентов).

## Before starting
- `02-project-init` пройден (Next-проект существует — реконструкция пишет в него).
- Chrome-плагин подключён (`list_connected_browsers` непустой).
- `opt-migrate-from-existing` пройден или идёт параллельно, если важны SEO/контент.
- `git tag pre-opt-visual-recreate` — точка отката.

## Boundaries
- **Always:** извлекать из живого DOM (не из выгрузки кода); скачивать реальные ассеты; коммит после каждой секции; вести лог отклонений.
- **Ask first:** замена лицензионного шрифта донора в проде; «улучшения» сверх нормализации (менять структуру/контент/смысл); удаление страниц донора.
- **Never:** воссоздавать фото генерацией вместо скачивания; ставить лицензионный шрифт (Druk и пр.) в прод без лицензии клиента; подтверждать OAuth/аккаунтные/платёжные согласия в браузере (cookie-баннеры — можно); жертвовать адаптивом ради пиксель-перфекта на десктопе (Tilda-абсолют → поток/grid).

## Done when
- Все секции главной собраны, каждая ≥90% по структурной оценке (или во флаге с причиной).
- Реальные ассеты донора скачаны/оптимизированы в `public/`, фото не воссозданы генерацией.
- Токены донора в `globals.css`; лог отклонений заполнен.
- Динамика (слайдеры/попапы/ховеры) воспроизведена или явно отложена с пометкой.
- `pnpm build` без ошибок; нет ошибок в консоли; адаптив корректен на 375 / 768 / 1280.
- Готово к запуску `08-seo-schema`.
