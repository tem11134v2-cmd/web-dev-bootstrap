**Цель внедрения.** Сейчас прогон прошёл, но в 4 точках разработчик вёл руками (см. §B). Надо, чтобы после правок шаблона будущий Claude проходил **сам, одним циклом: zero → вся главная страница, включая адаптив**. Ниже — проверенный workflow (§A), провальные паттерны которые надо запретить в спеке (§B), gotchas инструментов (§C) и конкретные правки (§D).

## §A. Проверенный автономный workflow (делать ОДНИМ циклом, не «по батчу за сессию»)

> Главное открытие каденса: **браузер НЕ узкое место**, как боялись в плане. `get_page_text` снимает весь текст страницы за 1 вызов, повторяющиеся секции строятся одним компонентом — поэтому ВСЯ главная реально собирается за один проход. Старое «одна секция/страница = одна сессия» — избыточно консервативно.

### Фаза 0 — Setup (один раз, серийно)
1. Детект платформы (Tilda: `t-rec`/`tildacdn`).
2. **Dev-сервер именно ЭТОЙ папки.** В worktree сервер на `:3000` обычно принадлежит главной папке и отдаёт старый билд → новые секции «не рендерятся». Поднять свой: `next dev -p <free>`; верифицировать (`curl`, и `grep` страницы на свежий контент).
3. Открыть донора в Chrome-плагине; **чистый захват**: скрыть cookie/попапы/чат через `display:none` (НЕ кликать «Принять»), повторять до чистого кадра.

### Фаза 1 — Bulk-извлечение (серийно, НЕМНОГО вызовов — в этом вся экономия)
1. ⭐ **`get_page_text` ОДИН раз → весь verbatim-текст страницы** (все секции + все повторяющиеся карточки разом). Это позвоночник. Заменяет десятки скриншотов. DOM-порядок текста = порядок секций → маппинг по индексу.
2. **Карта секций по геометрии** (record id / type / height) + **кластеризация одинаковых** (напр. 19 карточек модели = h≈608, type 396, содержат «Вместительность»).
3. **Токены** (computed styles) — палитра/шрифты/type-scale/контейнер/радиусы. Отдавать **плоской строкой** (`[text] fs/fw/color`), не объектом (см. §C блокировки).
4. ⭐ **Фиделити-базлайн по КАЖДОМУ непохожему блоку за 1 вызов:** для списка record-id вернуть `id :: bg :: главный-заголовок(text/size/weight/color)`. Это дёшево ловит «не тот фон/заголовок» ДО стройки (см. §B-1 — без этого я налажал).
5. **Bulk-ассеты** (query-стрипнутые base-пути): галереи по карточкам, общий набор иконок-удобств, фото секций, **соц-иконки + hrefs**, **id яндекс-карты (`um=constructor:…`)**, **поля форм** (placeholder/name).
6. Заморозить: токены→`globals.css`, тексты→data-файл, манифест ассетов.

### Фаза 2 — Ассеты (Node-скрипт, не вручную)
- Один `scripts/dl-*.mjs`: строит правильный Tilda-optim URL (`/-/resize/<w>x/-/format/webp/<file>.webp`; для уже-`.webp` источников — без повторного `format`), качает, раскладывает по слаг-папкам. Документирует провенанс. Крупные PNG (лого/фото) — прогнать через `sharp` (1.9MB→33KB).
- Политика веса: слайдеры-галереи тянуть **N первых** (3–4), не все ~10/карточку (иначе 180+ файлов).

### Фаза 3 — Сборка (без браузера, parallel-ready)
- **Сначала фундамент-компоненты:** контейнер `max-w-[1200px]`, пилюля r30, Druk-заголовок, **Socials** (общий, реальные иконки+ссылки), примитив слайдера (fade + стрелки). Они переиспользуются Hero/Showcase/Card/Footer.
- **Повторяющиеся секции → ОДИН компонент + массив данных** (`models-data.ts`: 19 карточек, `FEATURE_ICONS` map label→svg).
- **Непохожие секции → каждая свой компонент, СТРОИТСЯ ИЗ ИЗВЛЕЧЁННЫХ bg/heading/layout** (не «на глаз из токенов» — см. §B-1).
- **Mobile-first по построению:** база = всё в колонку; `lg:` = десктоп-раскладка донора (Tilda-абсолют → flow/grid). Кнопки `flex-wrap`. Хедер: гамбургер `<lg`.

### Фаза 4 — Верификация (`Claude_Preview`, объективно, НЕ скриншотом)
- На каждый брейкпоинт (375 / 768 / **1280 явной шириной**, см. §C): `preview_eval` → оверфлоу (`getBoundingClientRect().right > clientW`), `gridTemplateColumns`, битые `img` (`complete && naturalWidth===0`).
- На каждый блок: `eval`/`inspect` bg+heading против базлайна Фазы-1.4.
- Визуальный спот-чек: **Chrome viewport-скриншот** ключевых секций (НЕ `preview_screenshot` — виснет на длинной/слайдерной странице, §C).
- Сходимость: fail → фикс → re-eval, лимит ~4.

### Фаза 5 — Ссылки/интерактив
- Прокинуть извлечённые hrefs (соцсети, внешние), embeds (яндекс-iframe по `um=`), поля форм, якоря навигации (`#models`…), модельные «Заказать/Подробнее».

## §B. Провальные паттерны — спека ДОЛЖНА их запретить/выправить

> Это места, где модель (я) останавливалась или срезала угол, и разработчик правил руками. Автономность = убрать эти 4.

### B-1. ⛔ ГЛАВНОЕ: «построил из токенов на глаз» вместо извлечения → НЕВЕРНЫЙ дизайн
Hero и карточки я извлекал честно. А хвостовые блоки (LeadForm, Footer, Credit, Delivery, Video) на первом проходе собрал «on-brand из токенов» — и **промахнулся**: LeadForm сделал красной плашкой (донор — серая карточка как Availability), Footer тёмным (донор — белый), Credit по центру (донор — горизонтальный), Delivery 4-колонки с точками (донор — 2 колонки + карта России). Разработчик это поймал отдельным проходом.
**Урок:** премиса спеки «извлекать, не угадывать» должна применяться **РАВНОМЕРНО к каждому блоку**, не только к hero/карточкам. → Сделать §A-1.4 (фиделити-базлайн bg+heading по всем блокам) **обязательным гейтом ДО сборки**; в Boundaries добавить «Never: строить секцию из общих токенов без её собственного computed-style/скрина».

### B-2. ⛔ Остановка после «батча» (каденс-костыль)
Я собрал i5+i11+i13 и остановился, считая «один батч/сессия». Это эвристика из плана (когда думали, что браузер — бутылочное горло). С `get_page_text` это неверно. → В спеку: дефолт — **гнать всю страницу за цикл**; батчить только если страница реально огромная/просили.

### B-3. ⛔ Пропуск мобилки
Я отметил «адаптив корректен по построению», но **не проверил** (т.к. `resize_window` не работает) и не нашёл сам `Claude_Preview`. Разработчик направил. → В спеку: мобилка — **не опциональна**; `Claude_Preview` — штатный верификатор; «Done when» включает 0-оверфлоу на 375/768/1280, проверенный eval'ом.

### B-4. ⚠️ Консервативность по объёму
Ждал явного «делай всё». → В спеку/брифе: при выборе «перенос-реконструкция» автозапуск полного цикла без доп-подтверждений (объём страницы уточнять только если >N секций или многостраничник).

## §C. Gotchas инструментов и окружения (с решениями)

- **`javascript_tool` блокирует вывод шире, чем в спеке.** Не только «URL с query»: блокирует любые URL (иногда), **base64**, длинный/JSON-образный текст → `[BLOCKED]`. Надёжно проходит **короткий plain-text, newline/pipe-разделённый**. Приёмы: ассеты — стрипать `?query` (чистые tildacdn-URL проходят); текст секции — из `get_page_text` или скриншота; computed-styles — плоской строкой; большие списки — чанковать.
- ✅ **Адаптив = `Claude_Preview` MCP** (Playwright, реальный вьюпорт). `preview_resize` mobile(375)/tablet(768)/**custom W×H**; `preview_eval`/`inspect` объективны. `resize_window` Chrome-плагина НЕ сужает вьюпорт (innerWidth застревает ~2080) — не годится.
- ⚠️ `preview_resize` пресет **`desktop` = NATIVE окно превью (тут 360px!)** → для десктопа задавать ЯВНО 1280×800.
- ⚠️ **`preview_screenshot`/`inspect` ВИСНУТ (30с)** на: авто-слайдере (`setInterval`+transition), **очень высокой странице** (~15000px/156img), и **внешнем iframe** (Яндекс-карта — ждёт «idle» вечно). Чистка интервалов НЕ спасает. → Верифицировать `eval`'ом; визуал — Chrome viewport-скриншотом (он по экрану, не по всей странице).
- ⚠️ **`launch.json` на Windows + mise/corepack:** `pnpm`/`node` не на PATH спавнера → ENOENT. Рабочее: `runtimeExecutable` = АБСОЛЮТНЫЙ путь к `node.exe` (`process.execPath`), `runtimeArgs` = `["node_modules/next/dist/bin/next","dev","-p","<port>","--turbopack"]`. Один `next dev` на папку (два дерутся за `.next`).
- **React async render при проверке через eval:** клик/setState не отражается в ТОМ ЖЕ eval (рендер асинхронный). Проверять состояние **следующим** вызовом.
- **Tilda-специфика:** артборд ~1550px абсолют → переинтерпретировать в `max-w-[1200px]` flow/grid. Бейджи (`с ндс`/`в наличии`) + скрытый ribbon `ХИТ ПРОДАЖ!` (в DOM у всех карточек, визуально скрыт — не рендерить). Иконки-удобства — белые SVG (`_FFFFFF`) в красных квадратах. Карта — Яндекс-конструктор по `um=constructor:<id>` (переиспользовать id донора).
- **Biome vs Tailwind v4:** `biome check` ругается на `@theme`/`@apply` в `globals.css` («Tailwind-specific syntax disabled») — это не код секций, гейт = `pnpm build`. `<img>` для SVG-иконок даёт warning `noImgElement` — осознанно (next/image для SVG требует `dangerouslyAllowSVG`).

## §F. Докрутки (ревизия Claude по итогам критики) — дополняют §A–§D, не отменяют

- **F-1 (к §B-1): базлайн = bg + heading + LAYOUT.** Провалы Credit/Delivery были РАСКЛАДОЧНЫЕ («по центру vs горизонталь», «4 кол vs 2 кол+карта») — bg+heading их не ловит. Расширить §A-1.4: на блок вернуть ещё `flex-direction` / `grid-template-columns` / число прямых детей контейнера. Тогда гейт ловит «не та раскладка» ДО сборки.
- **F-2 (к §B-2): горло — КОНТЕКСТ, не браузер; бюджет ~5–10 страниц/сессия.** Дефолт каденса: **весь сайт за сессию, если ≤~5–10 страниц**; делить только бóльшие сайты или единичные гигантские страницы (~15000px). Чанк — по объёму контента, не по «батчу».
- **F-3 (к §C): разделить готчи.** В тело спека — УНИВЕРСАЛЬНЫЕ (блокировки `javascript_tool`, зависания `preview_screenshot`, biome+Tailwind v4, React async eval). В аппендикс «env-gotchas» — СРЕДА-СПЕЦИФИЧНЫЕ (`launch.json` mise/corepack PATH, `preview_resize desktop`=360, worktree-dev-сервер, SSRF-блок `next/image` на приватный IP). На нормальной машине часть из них не возникает — не засорять ядро.
- **F-4 ✅ РЕШЕНО (дефолт): близко к 1:1, но БЕЗ воспроизведения багов донора.** Строить точно по донору, НО кривые/несимметричные отступы и явный мусор НЕ копировать — снапить к разумному значению на чистых Tailwind-утилитах. Это происходит **естественно** при сборке (как в прогоне) → отдельная фаза нормализации и лог отклонений **НЕ нужны**. Полный «modernize»-редизайн (новый type-scale, переосмысление раскладки) — **НЕ делаем**. Формула: *верность донору + молчаливая чистка очевидного мусора, без деклараций*. (Спек: сформулировать допуск как «структурно 1:1, кривые отступы донора снапить к шкале» — не «pixel-perfect» и не «improve».)
- **F-5 (граница): §A-5 ссылки/формы = только ВИЗУАЛ.** Hrefs/embeds/поля-вид — да; рабочая отправка (`submitLead`, multi-sink) — спека 09. Спек обязан сказать прямо, иначе ложное ощущение «формы готовы».
- **F-6 (процесс): перенос вести в ОСНОВНОЙ папке проекта, не в worktree** (или жёстко документировать фикс dev-сервера из §A-0.2) — иначе «секции не рендерятся» (чужой `:3000`-билд) ловит каждый.

**Объективная верификация (плюс, зафиксировать как принцип):** §A-4 через `Claude_Preview` eval/inspect — это РЕШЕНИЕ проблемы «честного verifier» (программная проверка оверфлоу/grid/битых img + per-block базлайн вместо holistic-вкусовщины). Сделать это явным принципом спека, а не побочным приёмом.
