# План: opt-visual-recreate — визуальная реконструкция сайта-донора

**Статус:** спек написан и отревизирован по полному полевому прогону (2026-06-03). Решения ниже — исходный черновик (2026-06-02); журнал прогона и ревизии §F — в конце файла. Сам спек пишется ПОСЛЕ живого прототипа на реальном доноре — не за столом.
**Контекст:** обсуждение (владелец шаблона + Claude). Альтернативный путь миграции вместо «выгрузка кода → переделка под Next.js».

## Проблема

Выгрузка кода из Tilda/WP/конструкторов и переделка под Next.js стабильно проваливается: не тот дизайн, нет половины вёрстки, нет фоток, уродливо. Причина — экспорт-код это **шум**: модель одновременно reverse-инжинирит намерение из мусора, переводит чужую парадигму вёрстки (Tilda — абсолютное позиционирование на фикс-ширину) и достраивает невидимые ей ассеты → слишком много степеней свободы → дрейф. Вывод: выгрузка кода окупается только при reuse «как есть» на той же архитектуре.

## Как стыкуется с существующим (НЕ дубль)

`specs/optional/opt-migrate-from-existing.md` уже закрывает **контент + медиа + SEO/301 + cutover**. Дизайн там описан слабо («парсить палитру», «фотографируем со скриншотов») — отправляет на пересборку дизайна с нуля через `03→06`, а это и есть провальный путь.

`opt-visual-recreate` — **движок высокоточной реконструкции дизайна**, которого не хватает:

- **Композируется** с `opt-migrate-from-existing`: тот собирает тексты/медиа/редиректы + SEO-baseline → этот строит дизайн 90–95%.
- **Замещает** основные `03–06` (дизайн-система + главная + подстраницы) — по паттерну `opt-ecommerce` (тот замещает `05–06`).
- **Впадает обратно** в `08-seo` (берёт карту редиректов из opt-migrate) / `09-forms` / `10-analytics` / `11-performance` / `12-handoff`. Отдельная «спека дозакрытия» НЕ нужна — это и есть дозакрытие.
- Извлечённые токены кормят `03-design-system.md`.

## Ключевые решения

1. **Извлекать, не угадывать.** `getComputedStyle` (точные цвета/шрифты/отступы/радиусы/тени/брейкпоинты), реальные URL ассетов, текст verbatim — с ЖИВОЙ отрендеренной страницы через Chrome-плагин (`javascript_tool`, `get_page_text`, network). Скриншот — для *проверки*, не для съёма значений. Ассеты скачиваются и идут через sharp/`next/image` + cloudinary; фото не воссоздаются.
2. **Допуск 90–95%**, не пиксель-перфект. Очевидные баги чиним на лету эвристиками нормализации (снап отступов/шрифтов на шкалу, симметрия) + короткий **лог отклонений** (различать допуск и намеренное отклонение). Отдельной спеки «улучшения» нет.
3. **Платформенных веток в v1 нет** (WP-REST отложен). Дешёвый **детект** платформы — да (квирки: Tilda absolute positioning, WP пагинация). WP-REST вернуть для блогов/каталогов 100+ страниц.
4. **Полный автомат на самопроверках**, не на человеческих гейтах: swatch-проверка токенов ДО стройки; посекционная сходимость с жёстким лимитом (~4 итерации) — флаг-и-дальше, не вечный цикл; **структурная + программная** оценка (overlay-diff по сетке, проверка наличия ассетов / совпадения текста — без вкусовщины); финальный отчёт. Разовая ручная калибровка шага токенов на первом доноре — опционально.
5. **Мультиагент (Workflow) — фаза 2, отложено.** Целевая форма: независимый verifier (не самооценка builder'а) + параллельный fan-out по страницам/экранам ПОСЛЕ серийного фундамента (extract один раз → токены + layout + одобренный hero, заморожены как общие артефакты). Сначала наладить и откалибровать ОДИН поток builder→verifier. Но атом сразу делать **parallel-ready**: читает замороженные артефакты (не ходит на live), чистый I/O-контракт, раскладка файлов без коллизий (один компонент на секцию), стадия съёмки отделяема (браузер — один серийный ресурс).

## Алгоритм (целевой)

```
Фаза 0 (СЕРИЙНО, один раз): детект платформы → ЧИСТЫЙ захват (снять кадр → детект перекрытий →
        скрыть cookie/попапы/чат-виджеты через JS display:none, НЕ кликая «Принять» → переснять;
        повторять до чистого кадра) → extraction (computed styles: токены, 3 вьюпорта 360/768/1440,
        скачка ассетов по URL, скрейп текста) → заморозить артефакты. Дальше на live никто не ходит.

  Заметка по чистому захвату: баннеры/попапы часто без класса cookie/popup (на Tilda — `t657_rectangle`).
  Надёжный приём: найти по тексту кнопки-триггера → подняться к позиционированному контейнеру → display:none.
  НЕ кликать «Принять/Accept» (это согласие от имени юзера + не приватно). Self-check: повторять до чистого.
Фаза 1 (СЕРИЙНО): дизайн-система из токенов + layout + hero → swatch-проверка → [опц. калибровка].
Фаза 2 (ПАРАЛЛЕЛЬ/pipeline по страницам): на секцию builder → рендер → screenshot →
        verifier → (fail ⇒ builder с правками, max ~4) → pass.
Фаза 3 (СЕРИЙНО): merge + финальный отчёт (баллы по секциям, лог отклонений, флаги).
```

Трюк сходимости: полупрозрачный скрин оригинала поверх копии прямо в браузере (инжект через `javascript_tool`) — объективная улика по сетке/отступам.

## Развилка для пользователя

## Журнал: полный полевой прогон (2026-06-03, rus-campers.com — вся главная + мобилка)

Прогон от zero до **полной главной + адаптива** за один проход. Полный разбор — `_BUILD/v3/algorithm-improvements.md` (workflow §A / провалы §B / готчи §C / правки §D / ревизии §F). Сухой остаток:

**Что переломило модель плана:**
- **`get_page_text` снимает весь текст страницы за 1 вызов** → браузер **НЕ узкое место**, как боялись 2026-06-02. Повторы строятся одним компонентом → вся главная собирается за один цикл. Старое «секция/страница = сессия» — избыточно консервативно. Узкое место — **контекст**, бюджет ~5–10 страниц/сессия (ревизия F-2).
- **Объективная верификация = `Claude_Preview` `eval`/`inspect`** (Playwright, реальный вьюпорт): программная проверка оверфлоу / `gridTemplateColumns` / битых `img` + per-block базлайн — решение проблемы «честного verifier» вместо holistic-вкусовщины по скриншоту. `resize_window` Chrome-плагина для адаптива не годится (`innerWidth` застревает ~2080).

**4 точки, где модель вела руками (спека их теперь запрещает):**
- **B-1 (главное):** хвостовые блоки собраны «из токенов на глаз» вместо извлечения → неверный фон/заголовок/раскладка (LeadForm красной плашкой vs серая карточка; Footer тёмным vs белый; Credit по центру vs горизонталь; Delivery 4-кол vs 2-кол+карта). → Фиделити-базлайн **bg+heading+layout по ВСЕМ блокам — обязательный гейт ДО сборки**.
- **B-2:** остановка после «батча» (костыль старого каденса). → Дефолт: весь сайт за цикл.
- **B-3:** мобилка отмечена «корректна по построению», но не проверена. → `Claude_Preview` — штатный верификатор, 0-оверфлоу на 375/768/1280 в «Done when».
- **B-4:** ждал явного «делай всё». → Автозапуск полного цикла.

**Ревизии §F (вошли в спек):**
- **F-1** — базлайн расширен с bg+heading до **bg+heading+LAYOUT** (`flex-direction`/`grid-template-columns`/child-count): провалы Credit/Delivery были раскладочные, bg+heading их не ловит.
- **F-2** — горло = контекст, бюджет ~5–10 страниц/сессия; чанк по объёму, не по «батчу».
- **F-3** — готчи разделены: **тело спека** — универсальные (`javascript_tool` блокировки, зависания `preview_screenshot`, biome+Tailwind v4, React async eval); **аппендикс env-готчи** — среда-специфичные (`launch.json` mise/corepack PATH, `preview_resize desktop`=360, worktree-dev-сервер, SSRF `next/image`).
- **F-4 ✅ (дефолт):** **структурно 1:1, но БЕЗ воспроизведения багов донора** — кривые отступы снапить к шкале, мусор молчаливо чистить, без деклараций. Происходит естественно при сборке → **отдельная фаза нормализации и «лог отклонений» УБРАНЫ** (отличие от черновика-решения №2). Полный modernize-редизайн — не делаем.
- **F-5** — §Ссылки/формы = **только визуал**; рабочая отправка (`submitLead`, multi-sink) — спека `09`.
- **F-6** — перенос вести в ОСНОВНОЙ папке проекта (worktree-`:3000` отдаёт чужой билд → «секции не рендерятся»).

**Артефакты прогона:** компоненты `components/sections/*` + `components/layout/*` + `models-data.ts`; ассеты `public/images/{availability,models,showcase,social}/`; скрипт `scripts/dl-models.mjs`; коммиты `6bf73f9 → 107d7b3 → 92cd9dc → 25dc074 → c101eed`.

**Правки шаблона по итогам (эта сессия):** `specs/optional/opt-visual-recreate.md` переписан под §A (Фазы 0–5, один автономный цикл) + §F: `get_page_text` первым шагом, кластеризация повторов, фиделити-базлайн bg+heading+layout как гейт, верификация через `Claude_Preview`, каденс «весь сайт за сессию (≤5–10 стр.)», готчи тело/аппендикс, R10 без лога отклонений, R12 мультиагент-frozen-artifact.

**Третий проход (вопросы оператора, та же сессия):** (1) **discovery списка страниц** — sitemap-first (`/sitemap.xml`, WP `/wp-sitemap.xml`·`/sitemap_index.xml`) → краул nav/footer как фолбэк; раньше список молча делегировался в `docs/pages.md` от opt-migrate — дыра, если opt-migrate не было; + **scope-гейт** (показать человеку, подтвердить всё/подмножество/URL руками, связать с бюджетом R11).
