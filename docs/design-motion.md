# Design Motion — паттерны подачи и бюджет движения

Против «шаблонности»: как подать 44 типа секций (`docs/content-layout.md`) не бесконечными гридами карточек. Каталог паттернов подачи, правила анти-монотонности, бюджет анимаций. Читать на спеках 03/04 и при любых правках дизайна.

**Тип секции** отвечает ЧТО сказать (Benefits, Steps, FAQ), **паттерн подачи** — КАК показать (грид, табы, слайдер). Один тип можно подать разными паттернами; выбор диктует контент, а не привычка.

## 1. Каталог паттернов подачи

| Паттерн | Когда уместен (тип контента) | Чем строить | Цена |
|---|---|---|---|
| **Грид карточек** | 3–6 равнозначных пунктов, каждый читается сам по себе | CSS grid + `Card` | 0 JS. Дефолт-ловушка — см. § 2 |
| **Табы** | 3–7 альтернативных срезов, смотрят по одному: сегменты «для кого», варианты услуги, тарифы | shadcn `Tabs` | лёгкий client-остров |
| **Аккордеон** | 5+ пунктов с развёрнутыми раскрытиями: FAQ, ошибки, критерии выбора | shadcn `Accordion` | лёгкий client-остров |
| **Слайдер / карусель** | 4+ визуально насыщенных элементов: кейсы, отзывы, фото | shadcn `Carousel` (embla) | ~13 KB JS; автоплей — по § 3 |
| **Bento-grid** | 4–7 НЕравнозначных пунктов: 1–2 главных крупно, остальные мельче | CSS grid (`col-span`/`row-span`) | 0 JS |
| **Sticky-секция** | Длинный последовательный рассказ: визуал закреплён, текст скроллится (или наоборот) | CSS `position: sticky` | 0 JS |
| **Попап / hover-раскрытие** | Деталь по требованию: состав пакета, био участника, термин | shadcn `Dialog` / `HoverCard` | лёгкий client-остров |
| **Scroll-reveal** | Появление контента при скролле — универсальный «оживитель» любой секции | CSS + IntersectionObserver или `motion` | маленький client-остров |
| **Счётчики** | Stats: цифры внушительнее в движении | client-компонент, `easeOutExpo`, ~2 с | маленький client-остров |
| **Marquee** | Logo Bar > 8 логотипов; лента коротких отзывов | CSS `@keyframes` + дублированный трек | 0 JS; пауза по hover обязательна |
| **Параллакс-лайт** | Фон hero или CTA-баннера движется чуть медленнее контента | CSS scroll-driven animation или `motion` | дёшево в CSS; не на LCP-блоке |
| **До / после** | Визуальный результат: ремонт, клининг, дизайн, кузов | ползунок (client) или парные фото (0 JS) | JS только у ползунка |
| **Горизонтальный скролл карточек** | 5–10 карточек на мобильном: ряд со свайпом вместо километровой простыни | CSS `overflow-x` + `scroll-snap` | 0 JS |
| **Степпер / timeline** | Этапы, сроки, история — у контента есть порядок | CSS (flex + псевдоэлементы линий) | 0 JS |

«Цена» = сколько клиентского JS секция тащит. При прочих равных бери паттерн с 0 JS: серверная секция без гидрации быстрее и проще (см. `docs/architecture.md`).

### Заметки по реализации

- **Табы/аккордеон:** контент всех вкладок рендерится на сервере и есть в DOM — SEO не страдает. Дефолтная вкладка — самая продающая.
- **Слайдер:** первый слайд должен быть виден без JS (SSR-разметка), остальные догидрачиваются. Стрелки + точки, свайп на мобильном из коробки (embla).
- **Bento:** на мобильном схлопывается в одну колонку — проверь, что порядок чтения остаётся осмысленным.
- **Sticky:** на мобильном обычно отключается (`lg:sticky`, ниже — обычный поток); следи за высотой родителя.
- **Горизонтальный скролл:** добавляй видимый «хвост» следующей карточки (padding/peek) — иначе пользователь не понимает, что ряд скроллится.
- **Marquee:** трек дублируется дважды, `@keyframes` двигает на −50% — бесшовный цикл; `:hover { animation-play-state: paused }`.
- **Счётчики:** запускать один раз при входе в viewport (IntersectionObserver `once`), не на каждом скролле.
- **До/после (ползунок):** это client-компонент; для 0 JS — просто две подписанные фотографии рядом.

## 2. Анти-монотонность

Нарушение этих правил и есть «шаблонный AI-сайт»:

1. **Подряд — не более 2 секций одного паттерна раскладки.** Два грида подряд — предел; третий переделывай в табы / bento / аккордеон.
2. **На страницу — минимум 3 разных паттерна подачи** (не считая hero и CTA-полос).
3. **Сетка карточек — один из вариантов, не дефолт.** Пятый грид на странице — сигнал вернуться к каталогу, а не «так получилось».
4. **Паттерн выбирается ИЗ КОНТЕНТА:**

| Контент | Подача |
|---|---|
| 7 однородных пунктов | табы или аккордеон — НЕ грид из 7 карточек |
| Этапы / сроки / порядок | степпер или timeline |
| Сравнение (мы/другие, A/B, результат) | таблица или «до/после» |
| Сегменты «для кого» | табы — посетитель выбирает свой |
| 1–2 главных пункта + хвост | bento-grid |
| > 8 логотипов | marquee или карусель |
| Много фото одного кейса | слайдер или горизонтальный скролл |

5. **Чередуй плотность.** После плотной секции (грид, таблица) — воздушная (текст + фото, цитата, CTA-полоса).

## 3. Бюджет движения

- **Только `transform` и `opacity`.** Никаких layout-анимаций (`width`, `height`, `top`, `margin`) — они дёргают reflow. Канон производительности — `docs/performance.md`.
- **`prefers-reduced-motion` ОБЯЗАТЕЛЕН** для каждой анимации — сниппеты ниже. Пользователь с вестибулярными нарушениями или слабым устройством получает контент сразу, без движения.
- **LCP-блок не анимируется на загрузке.** H1 и hero-изображение видимы с первого кадра; scroll-reveal — только ниже первого экрана.
- **Максимум 1 «вау-приём» на экран:** счётчики ИЛИ параллакс ИЛИ marquee — не всё сразу.
- **Слайдер не автоиграет без паузы по hover.** При reduced-motion автоплей выключен полностью.
- Длительности: hover 150–300 ms; reveal 400–600 ms; счётчики ~2 с. Easing — семейство `ease-out`.

### Сниппет: хук + tailwind `motion-reduce:`

JS-анимации (счётчики, `motion`-острова, автоплей карусели) гейтуются хуком:

```tsx
// hooks/use-reduced-motion.ts
'use client'
import { useSyncExternalStore } from 'react'

const QUERY = '(prefers-reduced-motion: reduce)'
const subscribe = (cb: () => void) => {
  const mql = window.matchMedia(QUERY)
  mql.addEventListener('change', cb)
  return () => mql.removeEventListener('change', cb)
}
export function useReducedMotion(): boolean {
  return useSyncExternalStore(
    subscribe,
    () => window.matchMedia(QUERY).matches,
    () => false, // SSR: по умолчанию анимации включены
  )
}
```

```tsx
const reduced = useReducedMotion()
// счётчик: reduced → сразу финальное число, без анимации
// carousel: reduced → без автоплея
```

CSS-анимации гейтуются вариантом `motion-reduce:` (Tailwind, JS не нужен):

```html
<div class="animate-fade-up motion-reduce:animate-none motion-reduce:opacity-100">
```

Для собственных `@keyframes` (marquee и т. п.) — медиа-запрос в `globals.css`:

```css
@media (prefers-reduced-motion: reduce) {
  .marquee-track { animation: none; }
}
```

## 4. Тех-стек движения

Порядок выбора инструмента — от дешёвого к дорогому; если эффект достижим ступенью выше — вниз не спускайся:

1. **CSS**: tailwind `transition-*` / `hover:`, готовые классы `tw-animate-css` (уже в стеке), `@keyframes` в `globals.css` внутри `@layer` (не голым селектором — см. `docs/design-system.md` § «CSS-правила»). Покрывает hover-lift, marquee, степперы, scroll-snap, sticky.
2. **Маленький client-остров**: IntersectionObserver для scroll-reveal и счётчиков — свой хук, без библиотек:

```tsx
// hooks/use-in-view.ts
'use client'
import { useEffect, useRef, useState } from 'react'

export function useInView<T extends HTMLElement>(threshold = 0.2) {
  const ref = useRef<T>(null)
  const [inView, setInView] = useState(false)
  useEffect(() => {
    const el = ref.current
    if (!el) return
    const io = new IntersectionObserver(([entry]) => {
      if (entry.isIntersecting) {
        setInView(true)
        io.disconnect()
      }
    }, { threshold })
    io.observe(el)
    return () => io.disconnect()
  }, [threshold])
  return { ref, inView } // inView → добавить класс с transition/animation
}
```

3. **Пакет `motion`** (бывш. framer-motion) — опционально: только клиентские острова reveal/stagger со сложной хореографией. НЕ оборачивать серверные секции целиком в `motion.div` — секция станет клиентской («вирусный client» — `docs/architecture.md`).
4. **Интерактив** — только shadcn: `Tabs`, `Accordion`, `Dialog`, `Carousel`. Самописные табы/карусели не пишем.

## Чек-лист перед сдачей страницы

- [ ] ≥ 3 разных паттернов подачи; нигде нет 3 одинаковых раскладок подряд
- [ ] Паттерны выбраны из контента (этапы → степпер, сравнение → таблица/«до-после»...)
- [ ] Все анимации — только `transform`/`opacity`
- [ ] `prefers-reduced-motion` обработан везде (хук или `motion-reduce:`)
- [ ] LCP-блок статичен на загрузке
- [ ] ≤ 1 «вау-приём» на экран; слайдеры с паузой по hover
